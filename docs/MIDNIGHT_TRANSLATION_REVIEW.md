## Read this matrix correctly

- **GREEN: native representation available.** The feature can be expressed directly; the importer still needs a source-to-model correctness argument.
- **AMBER: executable but conditional/custom.** Code exists, often with tests, but representation/primitive assumptions remain.
- **RED: unavailable, rejected, incorrect, or not established.** These are distinct reasons, stated in each row.

A caller inherits the conditions of its callees. A helper using native integer arithmetic does not make an external-call transaction green. `MIDNIGHT_SUPPORT_INVENTORY.json` is coarse triage, not this semantic verdict.

## Concrete semantic defect found and repaired

**Getter return-memory clobber (material, reproduced on EVM).**

`midnight-lowering.mjs::compileGetter` previously emitted storage lookup expressions directly inside `.returnValues`. The backend packs return words starting at memory 0. Its mapping-address helper also writes key/base to memory 0/32. Later lookup evaluation therefore overwrote earlier output words. The first actual test run had 371 passes and exactly two failures: `testMarketStateGetter` and `testMarketStateAfterTake`. The trace returned the market ID and mapping base where the first two uint128 values belonged, causing the Solidity caller's decoder to revert.

Repair: bind every getter read before any return packing; pass local values to `.returnValues`. No source/test/proof edits. `test_midnight_getter_returns.mjs` checks all 12 autogenerated getters and reproduces the old scratch-clobber pattern as a negative control. The unchanged original two tests and all 373 suite tests now pass. Verity should ultimately make return-expression evaluation safe by construction.

## Backend memory contract: what changed, what is still assumed

1. Inspect the generated Yul's constant-address word stores. For this snapshot the highest word ends at byte 416. All such scratch/return/event space is reserved below the spill region.
2. Change ABI free-pointer initialization from 128 to `memoryguard(416)`. solc may reserve a region starting at 416 for its own spills and returns the first free pointer after it. The importer allocator uses that pointer and advances monotonically.
3. Relocate the final deployment `datacopy` from address 0 to `mload(64)` and return that slice immediately. Otherwise the large runtime copy would overwrite spill space.
4. Use checksum-pinned solc with `--optimize --yul-optimizations u --evm-version osaka`. The default optimizer still encounters stack failures; unrestricted inlining is not enabled here.
5. Record original/lowered Yul and bytecode hashes, scratch size, compiler hash and assumption status in `Midnight.backend.json`. Include the backend and CEI policy in artifact input digests.

Current source assembly reads buffers, reverts, deploys and uses arithmetic/transient storage, but has no arbitrary raw memory writes; `audit_midnight_memory.mjs` rejects newly encountered raw writers. Backend lowering rejects new mstore8/mcopy/codecopy mechanisms and changed deployment-copy shapes. These are conservative drift checks, **not a complete memory-safety proof**.

Dynamic writes in generated ABI/call/code-copy helpers must stay within fresh allocations at or above the free pointer; sources must remain valid/nonaliasing; narrow scratch writes must stay below the reserved boundary. These preconditions were inspected and tested on this pinned pipeline but are not mechanically proved. Future codegen/allocator changes require re-review. Do not apply this policy indiscriminately to other contracts or claim it is a verified general spilling pass.

## Pre-commit fork-validation finding

The actual tiny compiler regression established that pinned Verity accepts the CLZ verbatim intrinsic even when asked to compile for Cancun: `ExpressionCompile.lean:439` binds `_minFork` without enforcing it. The old experimental test expected a rejection and was stale after switching CLZ from an unknown named builtin to verbatim. The regression now explicitly records this upstream gap; it does not claim fork safety. The full pipeline explicitly selects Osaka in both Lean and pinned solc, so its tested target is unchanged. Upstream should enforce intrinsic minimum forks before expression compilation.
